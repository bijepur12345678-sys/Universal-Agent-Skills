# Software Engineering

## Trigger
Use for implementation, debugging, refactoring, architecture, API development, code review, and repository maintenance.

## Workflow
1. Inspect repository instructions, existing changes, entrypoints, dependencies, tests, and conventions.
2. Translate the request into observable behavior and acceptance tests.
3. Trace affected call paths; preserve established architecture.
4. Add/update a focused test, then implement the smallest correct change.
5. Keep interfaces typed, errors explicit, and changes scoped.
6. Consider security, accessibility, performance, and backward compatibility.
7. Run focused tests, relevant full suite, lint/format, and build where available.
8. Review diff for secrets, unrelated changes, generated noise, and missing docs.
9. Report exact files, commands, results, and remaining limitations.

Never claim tests pass without evidence or overwrite user changes without permission.
