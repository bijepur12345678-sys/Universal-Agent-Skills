# GitHub Source Research

## Trigger
Use when discovering or evaluating repositories, Skills, MCP servers, frameworks, datasets, or developer tools.

## Workflow
1. Search with task-specific queries and identify original upstream projects.
2. Inspect canonical README, exact source paths, license/NOTICE files, releases, recent commits, security policy, dependencies, and supported hosts.
3. Record canonical URL, immutable revision, release/version, update date, maintainer signals, runtime prerequisites, compatibility, and evidence URLs.
4. Classify as reference-only, independent reimplementation candidate, approved redistribution candidate, review-required, or rejected.
5. Compare with the existing catalogue and record exact/near-duplicate overlap.
6. Recommend a domain, registry ID, and next verification step.

Search snippets and badges are leads, not proof. Do not execute, install, or clone source code during read-only research. Unknown evidence remains unknown.
