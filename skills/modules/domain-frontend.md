# Domain Module: Frontend Development

## Trigger
Use for websites, frontend components, responsive interfaces, UI state, accessibility, browser performance, and design-system implementation.

## Workflow
1. Inspect framework, routes, existing components, styles, design tokens, and supported browser targets.
2. Identify primary user journeys, states, validation rules, error states, and responsive breakpoints.
3. Reuse the existing component system before introducing a new dependency.
4. Build semantic, keyboard-accessible markup with meaningful labels and focus behavior.
5. Keep loading, empty, success, error, and disabled states explicit.
6. Avoid layout shifts; optimize images, code splitting, and network requests when relevant.
7. Check contrast, reduced motion, screen-reader flow, and touch target usability.
8. Test at narrow and wide viewports, keyboard-only navigation, and representative browsers.
9. Verify console, network, and production build output.

## Outputs
A responsive, accessible interface with component-level and journey-level tests.

## Boundaries
Do not use visual polish as a substitute for usability or accessibility. Do not include real secrets in client-side code.
