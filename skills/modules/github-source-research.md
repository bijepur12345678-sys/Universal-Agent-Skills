# Internal Module: GitHub Source Research

## Trigger
Use when discovering repositories or evaluating sources for Skills, tools, MCP servers, frameworks, datasets, or workflows.

## Procedure
1. Search GitHub using task-specific queries.
2. Inspect the canonical README, license, release/tag, recent commits, and security policy.
3. Record the exact repository URL, default branch, latest stable version, meaningful update date, maintenance evidence, dependencies, compatibility, and security signals.
4. Inspect the exact files proposed for reuse. Never infer that all directories share the root license.
5. Classify the source as reference-only, reimplementation candidate, approved redistribution candidate, review-required, or rejected.
6. Compare the capability with existing catalogue entries and state likely overlap.
7. Record evidence URLs and the date checked.

## Required evaluation
Capture capability, target task, license scope, author, immutable revision, runtime requirements, agent compatibility, maintenance, security boundaries, duplicate assessment, domain placement, and decision rationale.

Search snippets and badges are leads, not proof. Do not execute, install, or clone source code during read-only research. Stars are not proof of quality or security. Unknown evidence must remain unknown.
